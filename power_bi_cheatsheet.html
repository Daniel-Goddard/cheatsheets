Power Query & M Language

ETL layer
ETL Process
ExtractConnect to multiple data sources (Get Data)
TransformClean, reshape & enrich data in the Power Query Editor
LoadClick Close & Apply to load the transformed table into the Data Model
Common M Transformations
Table.SelectRowsFilter rows matching a condition (UI: "Filter Rows")
Table.AddColumnAdd a new calculated column (UI: "Custom Column")
Table.GroupGroup rows & aggregate — Sum, Count, Avg, etc. (UI: "Group By")
Table.RenameColumnsRename one or more columns
Table.RemoveColumnsDrop columns you don't need
Table.TransformColumnTypesChange a column's data type
Table.SortSort rows ascending or descending
Table.NestedJoinMerge queries on a common key (UI: "Merge Queries")
Table.CombineAppend multiple tables with the same structure
Table.PivotTurn unique row values into new columns
Applied Steps — M Code
Every UI action is just sugar for a let…in expression
let Source = Sql.Database("myserver", "SalesDB"), dbo_Orders = Source{[Schema="dbo",Item="Orders"]}[Data], #"Filtered Rows" = Table.SelectRows(dbo_Orders, each [OrderDate] >= #date(2026,1,1)), #"Renamed Columns" = Table.RenameColumns(#"Filtered Rows", {{"Amt", "OrderAmount"}}) in #"Renamed Columns"
Parameters & Custom Functions
Reusable parameter
StartDate = #date(2026, 1, 1) meta [IsParameterQuery=true, Type="Date"]
Custom function, invoked as GetSalesForRegion("West")
let GetSalesForRegion = (region as text) => Table.SelectRows(Sales, each [Region] = region) in GetSalesForRegion
Query Folding
What it DoesPushes transformations back to the source system (e.g. generates equivalent SQL) instead of pulling all raw data in first
Check FoldingRight-click a step → "View Native Query" to confirm folding is still intact
Best PracticeFilter & aggregate early; custom columns and text transformations can break folding — keep them late in the sequence
Merge vs Append Queries
Merge QueriesJoin two queries side-by-side on a common column — adds columns (like a VLOOKUP/SQL JOIN)
Append QueriesStack two or more queries with the same structure — adds rows (like a SQL UNION ALL)

Data Modeling

star schema · relationships
Core Concepts
TablesA collection of related data organized in rows & columns
RelationshipsConnections between tables using common fields (keys)
CardinalityDefines the relationship type between two tables
Cardinality Types
One-to-Many (1:*)One dimension row relates to many fact rows — the standard, most common pattern
One-to-One (1:1)Exactly one row on each side — rare, usually indicates tables that could be merged
Many-to-Many (*:*)Multiple rows on both sides can relate — use carefully, can double-count if not modeled deliberately
Star vs Snowflake Schema
Star Schema (recommended)A central fact table connected directly to flat dimension tables — simpler, best performance, favored by the VertiPaq engine
Snowflake SchemaDimensions further normalized into sub-dimensions — saves storage, but adds join hops & is slower to query
Fact vs Dimension Tables
Fact TableThe "events" — one row per transaction/measurement, mostly numeric + foreign keys (e.g. Fact_Sales)
Dimension TableThe "who/what/when/where" — descriptive attributes used for filtering & grouping (e.g. Dim_Customer, Dim_Date)
Cross-Filter Direction
Single (→)Filter flows from the "one" (dimension) side to the "many" (fact) side — default & generally safest
Both (↔)Filters propagate in both directions — only for many-to-many bridge scenarios; can cause ambiguous paths if overused

DAX Fundamentals

measures · columns
DAX Objects
MeasuresDynamic calculations that change with filters & context — used in reports & visuals
Calculated ColumnsComputed column added to a table; calculated row by row & stored in the model
Calculated TablesCreates a new table using a DAX expression; stored in the model like a physical table
Basic DAX Functions
SUM(col)Adds all numeric values in a column
COUNT(col) / COUNTROWS(table)COUNT counts non-blank values in a column; COUNTROWS counts rows in a table
DISTINCTCOUNT(col)Counts the number of unique values in a column
MAX(col) / MIN(col)Returns the largest / smallest value in a column
IF(cond, t, f)Returns a value if a condition is TRUE, otherwise another
CALCULATE(expr, filters)Changes filter context to evaluate an expression — the most important DAX function
FILTER(table, cond)Returns a filtered table based on a condition
RELATED(col)Gets a value from a related table in a many-to-one relationship
Example Measures
Total Sales = SUM(Sales[Amount]) Sales 2025 = CALCULATE([Total Sales], 'Date'[Year] = 2025)
DAX Operators
+ − * /Addition, subtraction, multiplication, division
&Concatenation — joins two text values, e.g. [First] & " " & [Last]
= <> > < >= <=Comparison operators — equal, not equal, greater/less than (or equal)
&& ||Logical AND / OR (equivalent to the AND()/OR() functions)
Best Practices
Measures > ColumnsPrefer Measures over Calculated Columns for performance — Calculated Columns increase model memory
NamingUse meaningful names for Measures & other DAX objects
RELATED ScopeRELATED() only works in many-to-one relationships

Advanced DAX: Context

row · filter · transition
Context Types
Row ContextEvaluates a formula one row at a time — created by iterator functions like SUMX, FILTER, ADDCOLUMNS
Filter ContextThe set of filters currently applied — slicers, visuals, report filters, and surrounding CALCULATE
Context TransitionOccurs when CALCULATE converts Row Context into Filter Context — happens automatically inside CALCULATE()
Important DAX Functions
SUMX(table, expr)Iterator — adds an expression evaluated for each row, e.g. SUMX(Sales, Sales[Qty] * Sales[Price])
AVERAGEX(table, expr)Iterator — averages an expression evaluated for each row of a table
RANKX(table, expr)Returns the rank of a value within a table — tied values share a rank, and the next rank skips (1, 1, 3)
ALL(table/col)Removes all filters from a table or column
REMOVEFILTERS(table/col)Modern, more readable equivalent of ALL() for clearing filters inside CALCULATE
ALLEXCEPT(table, cols)Removes all filters except on the specified columns
VALUES(col)Returns distinct values from a column
SWITCH(expr, …)Evaluates an expression against multiple conditions
DIVIDE(num, den, alt)Safe division — handles divide by zero
VAR … RETURNStores a variable to improve readability & performance
Time Intelligence
SAMEPERIODLASTYEAR(dates)Shifts the current date filter back exactly one year
TOTALYTD(expr, dates)Cumulative total from start of year to the current filter date
DATEADD(dates, n, interval)Shifts the date filter by any interval — day/month/quarter/year
PARALLELPERIOD(dates, n, i)Shifts to the same relative period, matching the whole period rather than day-for-day
DATESYTD / DATESMTD(dates)Returns the year-to-date / month-to-date date range for use inside CALCULATE
Example — YoY Growth
YoY Growth % = VAR SalesCY = [Total Sales] VAR SalesLY = CALCULATE([Total Sales], SAMEPERIODLASTYEAR('Date'[Date])) RETURN DIVIDE(SalesCY - SalesLY, SalesLY)

Advanced DAX Patterns

calculate · running total · rank
CALCULATE — The Core Mental Model
Plain MeasureSUM(Sales[Amount]) simply sums whatever rows the current filter context leaves visible
CALCULATE's JobThe only DAX function that can modify filter context — takes the current context and layers new filters on top, replacing any existing filter on the same column
Context Transition Example
Inside a calculated column on the Sales table
Customer Total = CALCULATE(SUM(Sales[Amount]), ALLEXCEPT(Sales, Sales[CustomerID]))
Running Total
ALL() removes the date filter, FILTER re-applies a custom one
Running Total Sales = CALCULATE( [Total Sales], FILTER(ALL('Date'), 'Date'[Date] <= MAX('Date'[Date])) )
Percent of Total
Pct of Total Sales = DIVIDE( [Total Sales], CALCULATE([Total Sales], ALL(Products)) )
Ranking with RANKX
Ranks ignoring the current filter so ranks stay stable
Product Rank = RANKX(ALL(Products), [Total Sales], , DESC)
CALCULATE with Multiple Conditions
Comma-separated filter arguments act as AND
South Mouse Sales = CALCULATE( [Total Sales], Sales[Region] = "South", Sales[Product] = "Mouse" )
Same result built with FILTER + COUNTROWS
Big Orders = COUNTROWS(FILTER(Sales, Sales[Amount] > 500))
Interview Traps
SUM vs SUMXSUM just adds a column. SUMX does the math row by row first, then sums the results.
CALCULATE FiltersA filter argument inside CALCULATE replaces the visual's existing filter on that same column — it doesn't add to it.
DIVIDE's 3rd ArgumentDIVIDE(numerator, denominator, altResult) safely returns altResult (e.g. 0) instead of erroring on divide-by-zero.
Time Intelligence Needs a Date TableSAMEPERIODLASTYEAR, TOTALYTD, DATEADD etc. only work correctly against a contiguous calendar table marked as the official Date Table.

Filters & Interaction

slicers · drillthrough
Filter Types
Visual FilterApplies to a specific visual only
Page FilterApplies to all visuals on the current page
Report FilterApplies to all pages in the entire report
Slicer Types
Dropdown SlicerShows values in a collapsible dropdown list
List SlicerShows values in a list with checkboxes
Date SlicerFilters dates — Year, Quarter, Month, Day
Between SlicerA range slider — select a range of numbers or dates
Filters vs Slicers
FiltersRestrict data in visuals; usually hidden in the Filter pane; not directly visible to end users
SlicersA visual, on-canvas filter; always visible; users click/select values directly to filter interactively
Drill Actions & Navigation
Drill DownMove from higher-level data to lower-level detail (Year → Quarter → Month → Day)
Drill UpMove from lower-level data back to a higher-level summary
DrillthroughNavigate from a summary page to a detailed target page
Interactions Between Visuals
Cross FilteringSelecting data in one visual filters other related visuals
Cross HighlightingHighlights related data in other visuals without filtering — useful for comparison
Sync SlicersSynchronize slicer selections across multiple report pages
Filter PrecedenceVisual > Page > Report — the most specific filter wins

Security

rls · ols · gateway
Row-Level Security (RLS)
What it DoesRestricts which rows of data each user sees within a single shared report
Defined ViaA DAX filter expression on a role, under Modeling → Manage Roles
Dynamic RLS[SalesRepEmail] = USERPRINCIPALNAME() — filters automatically to the logged-in user
RLS vs OLS
RLS (Row-Level)Restricts rows of data; defined with DAX in the data model; dynamic per user
OLS (Object-Level)Hides entire tables, columns or measures from certain users; static, no DAX
Other Security Layers
Workspace RolesAdmin (full control), Member (create & share), Contributor (create & edit), Viewer (view only)
Data Privacy LevelsNone < Organizational < Private < Confidential — controls data movement between sources via the Privacy Firewall
Sensitivity LabelsPublic / Internal / Confidential / Highly Confidential — can encrypt & restrict sharing (Microsoft Purview)
Gateway SecurityOn-Premises Data Gateway supports Windows Auth, Kerberos & Service Principal; encrypts data in transit

Performance Optimization

query folding · star schema
Optimization Techniques
Query FoldingEnables Power Query to send transformations to the source — reduces data transfer
Star SchemaUse Star Schema with fact & dimension tables — improves DAX performance & simplifies relationships
Optimize RelationshipsAvoid many-to-many relationships; use single filter direction whenever possible
Reduce VisualsAvoid too many visuals on a single page; use only visuals that add business value
Incremental RefreshRefresh only new/changed data instead of the full dataset — greatly improves refresh time
Performance AnalyzerBuilt-in tool to identify visuals & DAX queries causing slow performance
Optimize DAXUse variables (VAR) to store intermediate results; avoid complex calculations in row context
Remove Unused ColumnsRemoves unnecessary columns from Power Query — reduces model size & memory usage
Aggregation TablesCreate Aggregation Tables for large datasets — redirects queries to smaller summary tables
Optimized DAX Example
Total Sales (Optimized) = VAR TotalQty = SUM(Sales[Quantity]) VAR TotalAmt = SUM(Sales[Amount]) RETURN IF(TotalQty > 0, TotalAmt, 0)

Best Practices & Mistakes

naming · modeling · theming
Best Practices
Naming ConventionsUse clear, consistent names; prefix tables with tbl_/dim_/fact_, measures with msr_
Folder OrganizationOrganize reports, datasets & dashboards in logical workspace folders
Reusable MeasuresAvoid hardcoding values; use variables & shared measures
Model OptimizationUse proper data types, remove unused columns, keep the model small and efficient
Consistent ThemesUse consistent colors, fonts & layouts following company branding
DocumentationDocument data sources, transformations & business logic
Common Mistakes
Flat TablesUsing flat tables without relationships leads to redundant data & wrong results — always use Star Schema
Too Many VisualsOverloaded reports confuse users & slow down performance
Duplicate CalculationsCreating the same logic in multiple measures/columns increases model size — use reusable measures
Poor RelationshipsIncorrect or many-to-many relationships lead to wrong results & poor performance
Ignoring PerformanceIgnoring DAX optimization, model size & refresh times — always test & monitor
Excessive Custom VisualsToo many custom visuals increase load time & maintenance effort

Power BI Interview Questions

top 20 — short & crisp answers
Import vs DirectQuery?Import stores data in memory for fast analysis. DirectQuery fetches data in real time from the source.
DAX vs M Language?DAX is used for data analysis & calculations. M Language is used in Power Query for data transformation.
Measure vs Calculated Column?A Measure is calculated on the fly and uses less memory. A Calculated Column is stored in the model and increases memory usage.
What is Row-Level Security (RLS)?RLS restricts data visibility at the row level based on user roles.
What is Star Schema?A data modeling technique with one fact table connected to multiple dimension tables.
What is Query Folding?It pushes transformations to the data source to improve performance.
What is a Gateway in Power BI?A Gateway acts as a bridge between on-premises data sources and the Power BI Service.
Dataset vs Report?Dataset is the data model. Report is the visual representation built on top of the dataset.
Dashboard vs Report?Report is interactive and ad-hoc. Dashboard is a single-page summary of pinned key visuals (tiles).
What is Incremental Refresh?It refreshes only new or changed data partitions, improving refresh time for large datasets.
What does CALCULATE() do?It changes the filter context used to evaluate an expression.
What is Filter Context?The set of filters applied to tables/columns that affect DAX calculations.
What is Context Transition?Converts Row Context to Filter Context — happens automatically inside CALCULATE().
What is a Dataflow?A dataflow prepares and stores data in the cloud for reuse across datasets and reports.
What are Workspaces?Workspaces are containers to organize and collaborate on Power BI content.
Cross Filter vs Cross Highlight?Cross Filter filters data in other visuals. Cross Highlight only highlights related data without filtering.
How can you optimize a slow report?Optimize the model, reduce visuals, use DAX best practices, enable Aggregations, and use Performance Analyzer.
What are Bookmarks?Bookmarks save the state of a report page (filters, slicers, visual states) for user navigation.
What is Drillthrough?Drillthrough navigates from a summary visual to a detailed target page.
Best practice for data modeling?Use Star Schema, proper data types, avoid bi-directional relationships, and keep the model clean.
